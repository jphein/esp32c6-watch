Slint UI · v0.7.0 · shipped

Four faces, one watch.

A single Theme.scheme selector routes 18 palette tokens through every screen. Fifteen Slint files keep saying Theme.accent — the value now follows the scheme, so all screens re-theme with zero per-screen edits. The choice is picked on-glass and persisted to flash.

4 schemes 18 tokens 15 screens follow automatically Slint 1.17 · no_std

01 — The faces

The four schemes

The clock face rendered in each scheme, faithful to the on-glass layout. Three ride true-black — self-emissive and battery-optimal on the AMOLED — plus one calm light theme.

02 — The picker

Live swatches, not chips

Tap a tile, the whole watch changes

Each tile is a live mini-preview painted in that scheme's own tokens — you see the theme, not a paint sample. Tapping sets Theme.scheme instantly for a whole-watch preview and emits theme-changed so Rust persists the choice.

  • A scene-resident Slint overlay — no framebuffer, no WiFi — reached from a SYSTEM launcher tile, the same idiom as WLED / Energy / Climate.
  • Right-swipe or the back-chevron closes; the active tile carries an accent ring and check.
  • Restored at boot and re-applied after a game exit, so the watch never snaps back to Midnight.

03 — The substrate

Token matrix

Eighteen tokens × four schemes. accent and warm stay bright in every scheme so near-black on-accent detail — button text, creature eyes, icon pips — always reads on them.

04 — Decisions

Worth flagging

AMOLED Paper costs power

Three dark schemes ride true-black #000000 — self-emissive-black, battery-optimal. Paper lights most pixels, so it draws more. Noted under the picker; not a blocker.

Contract on-accent stays near-black

accent and warm stay bright in every scheme so near-black detail always reads on them — no per-call conditionals anywhere.

AOD always true-black

The always-on display stays black with dim text regardless of scheme — a light AOD would defeat the power-saving point of the mode.

Flash config.rs v3

A SWCFG3 record appends one theme byte before the checksum. v1/v2 records still load (default Midnight); WiFi creds, page and units survive the upgrade.
